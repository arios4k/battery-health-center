# Battery Health Center 的工作原理

应用背后的细节，写给好奇的用户和贡献者。返回 [README](../README.zh-CN.md)。也提供
[English](HOW-IT-WORKS.md)、[Español](HOW-IT-WORKS.es.md)、[Deutsch](HOW-IT-WORKS.de.md) 和
[Français](HOW-IT-WORKS.fr.md) 版本。

- **电池数据**直接从 `/sys/class/power_supply/BAT*` 读取。同时支持基于能量（µWh）和基于电荷（µAh）的驱动。
- **充电上限**由 `bhc-helper` 写入 `charge_control_start_threshold` 和 `charge_control_end_threshold`，它是唯一
  以 root 身份运行的部分。它只使用 Rust 标准库（外加用于本地时间的 libc），只接受经过验证的参数，并且只写入
  这些 sysfs 文件、它在 `/etc` 中自己的配置文件（已保存的上限和充电计划），以及（为优化充电）
  `/var/lib/battery-health-center` 中的拔下电源时间列表。如果开启**重启后保留**，systemd 服务会在开机和从睡眠
  中恢复后重新应用上限。ThinkPad、许多华硕、戴尔、华为、LG、三星和 System76 笔记本电脑，以及其他带有阈值内核
  驱动的设备均受支持。
- **充电计划**需要已保存的充电上限，因为它会在您设定的每个时间之前的提前量（默认 2 小时）起，把上限解除到
  100%，直到该时间之后 30 分钟，然后再恢复。一个 root 权限的 systemd 服务（`battery-health-center-scheduler`，
  仅在存在计划时由 `.path` 单元启动）会完成这些操作，无需每次都询问密码。**优化充电**还会记录笔记本电脑
  接着电源至少 3 小时后您拔下电源的时间。当它在过去 28 天内，于工作日（或周末）看到至少 3 次这样的拔下电源，
  且相互间隔不超过一个半小时时，就会把该范围中较早的一端作为就绪时间。没有任何数据会离开您的电脑。
- **应用能耗**是估算值，因为 Linux 不会按应用测量功率。CPU 时间从 `/proc` 采样。进程根据 GNOME 启动每个应用时
  所用的 systemd scope 归入各个应用；对于会把进程转移到别处的应用（如基于 Chromium 的浏览器），则退而使用父进程。
  使用电池时，测得的高于空闲水平的功率会按 CPU 使用量在各应用之间分摊。
- **电源模式**使用 power-profiles-daemon 的 D-Bus API，与 GNOME 快速设置所用的相同。
- **历史记录**在应用运行期间每分钟保存一次到 `~/.local/share/battery-health-center/history.csv`。开启
  **在后台记录历史**可让应用在登录时隐藏启动。
- **更新与隐藏的副本。** 登录时启动的后台副本，在更新替换程序文件后仍会继续运行旧版本。它会察觉到这一点
  （Linux 会把被替换的文件标记为已删除），并在没有打开任何窗口时启动新版本然后退出。它每分钟检查一次，因此
  更新后约一分钟内新版本就会运行。
- **自适应工作区**：在较大的窗口中，“概览”、“健康”和“使用情况”使用两列。“充电”和“电源”使用居中的单列，使设置
  保持阅读顺序。当工作区宽度低于 820 逻辑像素时，仪表盘的各列会堆叠；窗口宽度低于 600 逻辑像素时，侧边栏变为
  返回导航。
- **保存失败**会显示在持久的横幅中，并给出受影响的路径和错误信息。首选项以原子方式替换，保存失败时会在内存中
  恢复。健康记录和已完成的应用使用小时数会在存储恢复后重试。如果电池样本写入失败，它们仍保留在内存中。
- **应用图标**随附于 `data/icons/hicolor/scalable/apps/io.github.BatteryHealthCenter.svg`；`docs/icon.svg` 是对应的
  文档副本。桌面条目、PolicyKit 提示、通知和“关于”对话框使用相同的应用 ID。从源码构建的版本会在“关于”对话框、
  通知和应用使用列表中直接加载源码中的图标，因此较旧的已安装图标不会将其覆盖。
